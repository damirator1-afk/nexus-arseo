# Nexus Arseo

Nexus Arseo — система поддержки решений по пополнению склада. Пользователь загружает доступные Excel-выгрузки, получает детерминированный расчёт потребности по SKU, проверяет числовое обоснование и формирует заказ поставщику.

Рабочий интерфейс: [https://nexus-arseo.vercel.app/replenishment](https://nexus-arseo.vercel.app/replenishment)

## Возможности

- загрузка произвольного числа поставщиков и нескольких файлов одного типа;
- чтение транзакций продаж, помесячных продаж, остатков, товара в пути, MOQ/кратности и остатков по партиям;
- поддержка обычных табличных выгрузок и иерархических отчётов 1С;
- сопоставление строк без SKU с каталогом поставщика по нормализованному названию, порядку слов и консервативному нечёткому сравнению;
- очистка регулярного спроса от единичных крупных продаж;
- компенсация подавленного спроса в вероятные периоды отсутствия товара;
- сезонность, ограниченный исторический тренд и внешний прогноз роста;
- статистический страховой запас по волатильности и целевому уровню сервиса;
- учёт резервов, подтверждённого товара в пути, сроков прихода и MOQ;
- защита от автоматического заказа медленных и прекративших продаваться позиций;
- показатели покрытия, предполагаемой даты исчерпания запаса, риска дефицита и избытка;
- группировка рекомендаций по поставщикам, подтверждение менеджером и экспорт заказа;
- подготовка сообщения для WhatsApp или Telegram без автоматической отправки;
- опциональное объяснение результата с помощью LLM поверх уже рассчитанных чисел.

## Принцип расчёта

LLM не участвует в вычислении рекомендаций. Расчёт выполняют чистые TypeScript-функции и при одинаковых входных данных всегда даёт одинаковый результат.

Упрощённая схема:

```text
очищенный спрос
  → сезонный прогноз и устойчивый рост
  → потребность на срок поставки и период пересмотра
  → статистический страховой запас
  → вычет доступного остатка и подтверждённых поставок
  → округление до MOQ/кратности
```

Базовая формула:

```text
target_position = forecast_over_horizon + safety_stock
current_position = max(0, current_stock - reserved_stock) + inbound_within_horizon
recommended_order = round_up_to_moq(max(0, target_position - current_position))
```

Страховой запас:

```text
safety_stock = z(service_level) × demand_std_dev × sqrt(lead_time + review_period)
```

Каждая рекомендация сохраняет промежуточные значения: базовый и плановый спрос, сезонные коэффициенты, рост, поправку на stockout, исключённые всплески, остаток, резерв, товар в пути, волатильность, уровень сервиса и страховой запас.

## Данные

Исходные книги выбираются пользователем в браузере. В репозитории нет встроенного клиентского набора данных, а приложение не зависит от фиксированных названий поставщиков.

Для каждого поставщика можно добавить любое количество файлов следующих видов:

| Источник | Для чего используется |
| --- | --- |
| Динамика продаж | Транзакции, накладные и выявление разовых крупных продаж |
| Продажи по месяцам | История спроса, сезонность и тренд |
| Остатки по месяцам | История доступности и оценка stockout |
| Товар в пути / операционная выгрузка | Поставки, текущий остаток, резерв, категория и цена при наличии колонок |
| MOQ и кратность | Приведение рекомендации к допустимому размеру заказа |
| Остатки по партиям | Остаток по складам и исключение товара с недостаточным сроком годности |

Необязательно иметь все источники. Для запуска нужен хотя бы один источник остатка: помесячный остаток, текущий снимок или остаток по партиям. Пропуски остальных источников показываются в интерфейсе вместе с применённым допущением.

Если помесячный отчёт не содержит кода SKU, Nexus Arseo сопоставляет товар только при достаточно надёжном совпадении с кодированной строкой из другого файла того же поставщика. Неоднозначные позиции не угадываются, исключаются из расчёта и выводятся пользователю отдельным предупреждением.

## Архитектура

```text
Браузер
  ├─ загрузка XLS/XLSX
  ├─ парсинг и нормализация
  ├─ сборка единой модели
  ├─ детерминированный расчёт
  └─ таблицы, аналитика, подтверждение и экспорт

Next.js server
  ├─ GET /api/health
  └─ POST /api/replenishment/narrate  (опционально)
```

Ключевые модули:

- `lib/nexus/replenishment/xlsxParsers.ts` — разбор поддерживаемых Excel-структур;
- `components/replenishment/shared.ts` — объединение файлов одного поставщика и подготовка нормализованных данных;
- `lib/nexus/replenishment/assemble.ts` — сборка общего входа расчёта;
- `lib/nexus/replenishment/calculation.ts` — детерминированный расчёт рекомендаций;
- `lib/nexus/replenishment/planSelectors.ts` — агрегаты дашборда;
- `components/replenishment/ReplenishmentWorkspace.tsx` — клиентский сценарий загрузки, расчёта и просмотра;
- `app/api/replenishment/narrate/route.ts` — серверное LLM-объяснение готовой рекомендации.

Файлы и вычисляемый план не отправляются на сервер. При запросе AI-объяснения сервер получает только значения одной уже рассчитанной рекомендации. Модель не может менять итоговое количество; при отсутствии ключа или ошибке сети детерминированное объяснение остаётся доступным.

## Локальный запуск

Требования:

- Node.js 22 или новее;
- npm 11 рекомендуется для воспроизводимости lockfile.

```bash
npm ci
npm run dev
```

Откройте [http://localhost:3000/replenishment](http://localhost:3000/replenishment).

Production-режим:

```bash
npm run build
npm run start
```

## Переменные окружения

Создайте `.env.local` при необходимости. Реальные секреты не должны попадать в Git или Docker image.

| Переменная | Обязательность | Назначение |
| --- | --- | --- |
| `OPENAI_API_KEY` | Нет | Включает серверное AI-объяснение рекомендации |
| `OPENAI_MODEL` | Нет | Модель для объяснения; по умолчанию `gpt-5-mini` |
| `NEXUS_PORT` | Нет | Порт хоста для Docker Compose; по умолчанию `3000` |

Без `OPENAI_API_KEY` загрузка файлов, расчёт, аналитика, подтверждение и экспорт продолжают работать полностью.

## Docker

Сборка и запуск:

```bash
docker compose up --build
```

Интерфейс будет доступен на [http://localhost:3000/replenishment](http://localhost:3000/replenishment), health endpoint — на [http://localhost:3000/api/health](http://localhost:3000/api/health).

Другой порт хоста:

```bash
NEXUS_PORT=8080 docker compose up --build
```

В PowerShell:

```powershell
$env:NEXUS_PORT=8080
docker compose up --build
```

Остановка:

```bash
docker compose down
```

Ключ можно передать через окружение или локальный `.env`, который не копируется в image:

```bash
OPENAI_API_KEY=... docker compose up --build
```

## Ограничения и допущения

- Stockout определяется эвристически по истории остатка и соседнему спросу, если явного индикатора нет.
- При отсутствии транзакций помесячный спрос используется без очистки разовых накладных.
- Товар в пути без подтверждённой даты показывается как риск, но не уменьшает заказ.
- При отсутствии категории применяется нейтральный уровень сервиса `UNCLASSIFIED`.
- Срок поставки, период пересмотра, внешний прогноз и уровни сервиса задаются пользователем как плановые параметры.
- Цена используется только для отображения суммы заказа и не влияет на количество.
- Подтверждение и отправка заказа остаются действиями человека: приложение не размещает заказ автоматически.

## Безопасность

- секреты читаются только из environment variables;
- `.env*`, `node_modules`, build artifacts и Git metadata исключены из Docker context;
- экспортируемые CSV-значения защищаются от spreadsheet-formula injection;
- LLM получает готовые числа и возвращает только текстовое объяснение по строгой JSON-схеме;
- `/api/health` не проверяет внешние сервисы и пригоден для container healthcheck.
